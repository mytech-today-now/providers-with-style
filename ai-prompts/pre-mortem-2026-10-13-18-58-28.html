Issue 01

Imported metadata can execute markup when a dataset is displayed

Core finding

Kind
Core
Priority
P1, remediate before normal release
Severity
Severity 1 (Critical)
Likelihood
Possible, because import is a first-class workflow and remote directory results can be saved and displayed.
Impacted area
Security, confidentiality of same-origin browser data, stored provider records, user trust.

Failure mode

A dataset can provide longDescription through local JSON import, remote JSON import, or the metadata editor. The active v14 display path assigns that value to innerHTML. A malicious or accidentally active markup string can therefore be parsed as document markup when the dataset is displayed. The existing renderSafeRichText helper is used for the proscons field, but not for the dataset description.

Evidence or rationale

  • public/provider-hub-v14.js:533-553 defines a constrained rich-text renderer for record descriptions.
  • public/provider-hub-v14.js:954 assigns data.longDescription directly to longDesc.innerHTML.
  • public/provider-hub-v14.js:1134-1172 accepts longDescription without sanitizing or type-checking it.
  • public/provider-hub-v14.html:222 labels the field as allowing HTML. Local and remote JSON import paths are in public/provider-hub-v14.js:1333-1361 and 1555-1679.
  • The v16 JavaScript copy contains the same direct sink at providers-with-style/providers/provider-hub-v16.js:1023.

The unsafe data-to-HTML path is confirmed by source inspection. Browser execution and data theft were not exercised. Exploitability and impact should be confirmed with a harmless local fixture before release.

Why this matters

Imported content is often supplied by another person or remote directory. When active markup is interpreted in the application origin, it may be able to inspect the same origin's IndexedDB, preferences, and Maps key. This risk is separate from displaying harmless formatting and cannot be resolved by escaping only the visible table cells.

Recommended mitigation

Use the existing constrained rich-text renderer for descriptions if formatting is part of the contract, or assign plain text through textContent. Validate that metadata is a string before rendering. Apply the same rule to every maintained runtime version and keep external attributes and URLs out of the allowlist. If HTML formatting remains supported, document the small allowed tag set and strip all attributes except the existing safe class allowlist.

Core finding

Kind

Severity

Failure mode

The directory parser collects JSON links from HTML, manifests, and text listings, resolves them against the returned document URL, and fetches every discovered candidate. The only URL check is HTTP or HTTPS. A directory can therefore cause the browser to request JSON files on additional origins without naming those origins to the user first. Cross-origin fetch uses the browser's CORS behavior and does not set cross-origin credentials, so this is not server-side request forgery and is not a CORS bypass.

Evidence or rationale

  • public/provider-hub-v14.js:1472-1518 collects links and manifest URLs.
  • public/provider-hub-v14.js:1600-1660 fetches discovered sources in a loop.

Testable assumption: a remote listing may link to a tracking host or a state-changing GET endpoint ending in .json. Confirm with a controlled two-origin test server and observe request destinations and headers.

Why this matters

A user may understand the action as loading one directory while the browser contacts several hosts. Those hosts learn the requester's network address and may receive referrer metadata. Requests can also trigger server behavior even when the browser later refuses to expose the response through CORS.

Recommended mitigation

Retain the intended cross-origin import feature but make each distinct origin visible before requesting it. Require an explicit user choice for newly discovered external origins, revalidate after redirects, and keep credentials off cross-origin requests. Consider a same-origin-only default if product requirements allow it. Bound the number of origins and files. Explain failed CORS reads without implying the request was never sent.

Core finding

Kind
Core
Priority

Severity
Severity 2 (High)
Likelihood

Failure mode

Local imports read each entire file as text before parsing. Remote imports read the complete response body as text. Directory imports can discover and process an unbounded number of files and records. No byte, row, nesting-depth, or total-file limit is enforced at these boundaries. A large or deeply nested input can stall the tab, exhaust memory, or leave partially imported data.
